## 2. Logic Chain
1. **Scoping and Configuration**:
   - The user opens `/exercise` which renders the `ExerciseWizard` (Campaign Launcher). Scoping configurations (`campaignDetails`, `selectedTTPs`) define the parameters of the test. The attack chain code is generated in `campaignPayload`.
2. **Simulation Execution**:
   - During simulation, each procedure's execution and detection telemetry is logged under the `testResults` array.
3. **Data Finalization**:
   - Upon clicking "Complete", `finishExercise` compiles these outcomes.
   - For each TTP, `getAggregatedScore` averages the individual procedure scores (Prevented = 100, Alerted = 75, Logged = 50, Missed = 0). TTP outcome is marked high (blocked) if the average is >= 60, medium if >= 25, else low (missed).
   - If an event is missed or logged, a corresponding gap is created and pushed to the global `gaps` state, assigning a priority score (`priorityScore = Math.round(baseScore * visibilityMultiplier)`).
   - `completeExercise` updates exercises and resolves existing gaps if the outcome status is high (blocked).
4. **Data Persistence**:
   - React state updates trigger `useEffect` hooks in `AppContext.jsx`, executing `localStorage.setItem` to persist the data to the browser storage under the specific keys.
5. **Aggregation & Reporting**:
   - When visiting `/reports`, `Reports.jsx` reads `exercises` and `gaps` from the application context.
   - It groups exercises by campaign name.
   - It incorporates orphaned or manually added gaps from the `gaps` state so they are not omitted.
   - For the selected campaign, it dynamically calculates overall coverage counts (High, Medium, Coverage Gaps) by checking the average outcomes of the procedures stored in the `campaignSummaries[selectedCampaign]` object.
   - Finally, it renders the results (scoping, summary text, findings table) and renders the PDF output using `@react-pdf/renderer` for user export.

## 3. Caveats
- Since EDR telemetry verification depends on manual inputs during Step 3, the final report metrics rely on the user inputting the correct actual outcomes.
- External API calls for AI generation (mapping TTPs, generating payloads, and summaries) depend on the configuration of Gemini/OpenAI API keys in environment variables or application settings.
- Legacy exercises (which do not have rich event/procedure results in `campaignSummaries`) do not support dynamic drilldowns and display basic mapping tables.

## 4. Conclusion
- The Campaign Launcher (`ExerciseWizard.jsx`) handles scoping, designing, executing, and finalizing EDR simulations.
- Campaign data is mapped back to MITRE TTPs and stored in React AppContext states synced directly to local storage keys (`exercises`, `gaps`, `campaignSummaries`, `campaignEvidence`).
- The Reports component (`Reports.jsx`) groups exercises, integrates orphaned gaps, dynamically aggregates metrics (blocked, medium, missed) from event outcomes, and provides both an interactive drilldown UI and a PDF export component (`ReportPDF.jsx`).
